# Текущее состояние проекта «Слабое тело»

Срез исходников на 21 октября 2026 года. Это первоначальный аудит репозитория, а не аудит работающего FirstVDS/Selectel или пользовательских данных.

## Архитектура

- Клиент: `index.html` (одностраничное приложение; разметка, CSS и большая часть клиентской логики в одном файле), библиотека программ/упражнений — `program-library.js`, изображения — `assets/`.
- Сервер: `server.mjs`, Node.js ESM и встроенный `node:http`; в том же процессе выдаются статические файлы и API. Внешние интеграционные функции питания находятся в `nutrition-source.mjs`.
- Данные: `data/accounts.json` содержит аккаунты, их данные, хеши паролей и сессии; запись сериализуется очередью во временный файл с переименованием. Аватары размещаются в `data/avatars`. Каталог продуктов — `data/nutrition-catalog.json`.
- Админка: `admin.html` и `/api/admin/*`; `RITM_ADMIN_LOGIN` назначает владельца, а сервер отдельно проверяет сессию и полномочие на каждом административном API-запросе.
- Запуск по README: Node.js 20+ и `node server.mjs` на `http://localhost:8766/`. Для публикации документация требует HTTPS reverse proxy, постоянное хранилище `data` и `RITM_SECURE_COOKIE=1`.
- В репозитории нет `package.json`, стандартных npm-скриптов и обнаруженных отдельных файлов тестов. Сторонние runtime-зависимости не заявлены.

## Реализовано по исходникам

- Регистрация и вход по логину/паролю; пароли хешируются через scrypt, сессионный токен хранится в виде SHA-256-хеша, cookie — HttpOnly и SameSite=Strict.
- Персональные данные тренировок синхронизируются через `/api/data`; есть профиль, экспорт, аватары, незавершённая тренировка, таймер, запись упражнений, завершение занятия, история, графики и цели.
- В библиотеке исходников 15 записей программ и 88 упражнений. В UI/каталоге могут применяться отдельные фильтры; количество исходных записей не означает, что все они видны пользователю.
- Питание включает локальный каталог из 164 продуктов на дату аудита, импортёр каталога и серверный поиск/штрихкод через Open Food Facts; поиск требует авторизованной сессии.
- Административный интерфейс предоставляет сводку и ограниченный список аккаунтов. По исходникам этот API не возвращает парольные хеши или отдельные дневниковые записи.
- Подключён Telegram WebApp SDK и адаптируются viewport/safe areas. Серверной проверки Telegram `initData`/аутентификации в просмотренных исходниках не обнаружено.

## Исправления в локальной рабочей копии

- Статическая выдача в `server.mjs` ограничена главной страницей, админкой, библиотекой программ и изображениями `.jpg/.jpeg/.png` из `assets/`. Запросы иных путей и методы кроме GET/HEAD отклоняются; реальные пути дополнительно проверяются против выхода за корень и папку ассетов, включая симлинки.
- `save()` в `index.html` теперь ждёт успешный ответ `/api/data`, только после него обновляет локальную копию и возвращает успех. Обработчики, изменяющие данные, ожидают результат; при отказе API текущие операции откатываются и не показывают сообщение об успехе.
- Нажатие на тренировку открывает предпросмотр с описанием и параметрами упражнений. Из предпросмотра можно открыть технику каждого упражнения и вернуться назад; запись подходов там скрыта. Таймер и активная сессия создаются только после кнопки «Начать тренировку». Саму тренировку можно продолжать по кликабельному таймеру в верхней панели.
- Allowlist и API записи проверены интеграционно на временной изолированной базе. Во встроенном браузере на отдельной локальной базе проверены регистрация временного тестового профиля, каталог → предпросмотр → карточка упражнения → возврат, скрытие записи до старта, начало занятия с появлением таймера и возврат к активному занятию кликом по таймеру. Клиентский сценарий ожидания ошибки сохранения проверен по коду и синтаксису; отказ API через браузер отдельно не запускался. Рабочие и пользовательские данные не затрагивались.
- 22 октября: раздел «Тренировки» перестроен по выбранным пользователем программам — четыре недели идут одной страницей, верхняя панель недель закрепляется при прокрутке и показывает текущую неделю, а большие обложки у карточек тренировок убраны. Если программ нет, отображается только предложение выбрать или создать программу. Проверены пустое состояние на пользовательском локальном приложении без изменений аккаунта и полный список нескольких программ/переход активной недели при прокрутке на отдельном временном локальном профиле.
- Кнопка выбора программы в пустом состоянии тренировок открывает отдельное модальное меню-каталог с поиском, фильтрами, описаниями и составом планов. Добавление записывает программу в личный список тренировок и возвращает пользователя к разделу тренировок; общий раздел «Программы» остаётся отдельным. Синтаксис клиентского скрипта проверен; визуальный сценарий не проверен, так как локальная вкладка при перезагрузке показала экран входа, а изолированный сервер не смог открыть порт в этой среде.

## Остаточные находки и приоритеты

Оценки ниже предварительные и основаны на исходниках. Продакшен-сервер, нагрузка и его конфигурация не проверялись.

### P2 — один JSON-файл и один процесс — ограничение роста

- **Факт:** все аккаунты хранятся в одном `accounts.json`, сервер записывает цельный снимок состояния; лимитер попыток входа находится в памяти процесса.
- **Влияние:** модель проста для текущего малого масштаба, но конкурентная работа нескольких экземпляров, восстановление и масштабирование требуют отдельного решения. Фактическая нагрузка неизвестна.
- **Эффект:** определить порог перехода на транзакционное хранилище и проверить резервное копирование/восстановление.
- **Сложность:** высокая для миграции; **риски:** потеря данных при неверном переносе; **зависимости:** метрики нагрузки, резервная копия, миграционный план.
- **Готовность:** миграция проверена на копии и имеет проверенный rollback и сверку записей.

### P2 — Telegram Mini App не подтверждает пользователя на сервере

- **Факт:** клиент подключает Telegram SDK и применяет оформление/размер viewport; в `server.mjs` не найден валидатор `initData`.
- **Влияние:** Telegram-контекст сам по себе не создаёт доверенную авторизацию и остаётся отдельным от аккаунтной сессии.
- **Эффект:** при продуктовой необходимости можно связать Telegram-пользователя с аккаунтом через проверяемый сервером flow.
- **Сложность:** средняя/высокая; **риски:** подмена идентичности, утечка аккаунта при неосторожной привязке; **зависимости:** согласованный сценарий привязки и способ безопасного хранения bot token.
- **Готовность:** сервер валидирует подпись/время данных Telegram, привязка не допускает захват чужого аккаунта и проверена негативными сценариями.

### P2 — определить поведение ограничения входа за reverse proxy

- **Факт:** лимитер использует `req.socket.remoteAddress`; адреса прокси и его конфигурация в этом аудите недоступны.
- **Влияние:** за прокси лимит может применяться ко всем посетителям совместно либо вести себя иначе, чем ожидается.
- **Эффект:** проверить фактический адрес сокета в размещённой конфигурации и выставить безопасную политику.
- **Сложность:** низкая/средняя; **риски:** доверие поддельному forwarded-заголовку; **зависимости:** конфигурация reverse proxy.
- **Готовность:** проверено, какой IP видит Node; forwarded-заголовки принимаются только от доверенного прокси.

### P3 — админ-аудит записывает события, но не имеет отдельного просмотра

- **Факт:** сервер хранит до 1000 последних обращений к сводке и списку аккаунтов; отдельная страница журнала в `admin.html` не обнаружена.
- **Влияние:** журнал трудно использовать для расследования админских действий.
- **Эффект:** небольшая read-only страница аудита, если это нужно владельцу.
- **Сложность:** низкая; **риски:** чрезмерное раскрытие персональных данных; **зависимости:** согласование состава отображаемых данных и периода хранения.
- **Готовность:** доступ только администратору, минимизация полей и проверка серверного контроля доступа.

## Проверки и ограничения аудита

- Проверено состояние Git, документация, основные маршруты/обработчики и локальные конфигурационные файлы без чтения `data/accounts.json` или секретов.
- Выполнены `node --check` для `server.mjs`, `nutrition-source.mjs`, `import-nutrition-catalog.mjs`, `program-library.js`; синтаксических ошибок не выведено.
- Проверен синтаксис одного inline-скрипта в `index.html` и одного в `admin.html` через `vm.Script`; обе проверки прошли.
- Прочитан JSON-каталог продуктов и импортирована библиотека программ в Node: получено 164 продукта, 15 программ и 88 упражнений.
- Read-only аудит серверной авторизации/админки выполнен отдельным встроенным Codex субагентом и сверён с исходниками.
- На отдельном процессе с временной пустой папкой данных проверены доступность главной страницы, админки, библиотеки и всех изображений; отклонение служебных путей и POST к статике; регистрация тестового аккаунта; закрытие админ API без сессии; доступ настроенного администратора; сохранение и чтение данных. Проверка завершилась `PASS`, временная папка удалена.
- Не запускались браузерные сценарии; не проверялись хостинг, DNS, HTTPS, работающий сайт, содержимое аккаунтов, сборка и нагрузка. Автоматических тестов/сборочных скриптов в корне не найдено.
- После первоначального аудита во встроенном браузере дополнительно проверен сценарий раздела тренировок, описанный выше; этот результат относится к локальной версии, не к работающему сайту.
