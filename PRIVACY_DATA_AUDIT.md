# Аудит персональных данных «Слабое тело»

**Дата аудита:** 23.10.2026  
**Объём:** актуальные исходники текущего checkout, документация, конфигурационные имена и локальные скрипты развёртывания. Значения `.env`, `data/accounts.json`, пользовательские данные, секреты и файлы аватаров не читались. Production-хост, договоры с провайдерами и фактические журналы хостинга недоступны из исходников.

## Архитектура

- Клиент: обычные HTML/CSS/JavaScript в `index.html`, `program-library.js`, `coach.js`; стороннего frontend-фреймворка не обнаружено.
- Сервер: Node.js ESM, встроенные `node:http` и файловые API; отдельной SQL/NoSQL БД и стороннего backend-фреймворка нет.
- Основное хранилище: `${RITM_DATA_DIR || <корень проекта>/data}/accounts.json`; локальные аватары — `${dataDir}/avatars`. В README описан persistent data directory `/var/lib/slaboetelo`, но это документация, а не подтверждение текущей production-конфигурации.
- В браузере: `localStorage` хранит локальную копию нормализованных данных приложения и пользовательские настройки. `sessionStorage` в просмотренных исходниках не найден.
- Авторизация: логин и пароль; пароль хешируется scrypt с солью, сессионный токен выдаётся cookie `ritm_session` (HttpOnly, SameSite=Strict, срок 30 дней; Secure зависит от `RITM_SECURE_COOKIE`). Сервер хранит хеш токена сессии. Email/телефон/OAuth/Telegram-вход не реализованы; добавлена отдельная необязательная связь Telegram-чата для сообщений бота.
- Среда: `RITM_DATA_DIR`, `PORT`, `RITM_HOST`, `RITM_SECURE_COOKIE`, `RITM_OFF_USER_AGENT`, `RITM_ADMIN_LOGIN`, `NODE_ENV`, `RITM_TELEGRAM_BOT_TOKEN`, `RITM_TELEGRAM_WEBHOOK_SECRET`, `RITM_TELEGRAM_BOT_USERNAME`, `RITM_PUBLIC_URL`. Содержимое значений не исследовалось и не раскрывается.
- Сторонние запросы: поиск Open Food Facts по названию или штрихкоду с сервера; при включённой пользователем интеграции — Telegram Bot API для ответов на команды и отправки выбранных уведомлений. Клиент загружает официальный Telegram Web Apps SDK; имя из SDK используется только для приветствия. Валидации Telegram `initData` для входа нет, поэтому это не способ аутентификации.
- Аналитика/реклама/платежи/OAuth/почтовые рассылки: вызовы этих интеграций в текущих исходниках не найдены. В приложении есть внешняя ссылка на справочный материал Роспотребнадзора.

## Проверка удаления, экспорта и пользовательских запросов

- **Экспорт** есть в профиле. Он сохраняет текущую структуру данных профиля/дневника в JSON-файл браузера; он не содержит пароль и не является полной выгрузкой серверных журналов, заявок/аудита/истории сессий.
- **Удаление аккаунта** требует текущую сессию, пароль и точное подтверждение логина; админский аккаунт удалять нельзя. Удаляются аккаунт, сессии, аватар (если больше не используется), заявки, приглашения, связи и аудиты, связанные с логином, а также связка Telegram, одноразовые коды и очередь сообщений.
- Удаление **не может стереть** экспортированные файлы пользователя, локальный кэш на иных браузерах/устройствах и резервные копии, для которых ещё не установлен срок. Нельзя обещать уничтожение в этих местах без инфраструктурного процесса.
- Отдельной формы запроса доступа/исправления/отзыва согласия нет. Ссылка в профиле направляет на email оператора; нужно подтвердить, что адрес принадлежит оператору и доступен для обработки обращений.
