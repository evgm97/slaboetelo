# Стандарт данных упражнения

## Текущее состояние

- `program-library.js` содержит каталог программ и список библиотечных упражнений. Программа хранит метаданные и предписания по дням; предписание включает `exerciseId`, режим, подходы, повторения/время, отдых, RIR и примечание.
- В конце массива `exercises` многие библиотечные записи содержат только `id` и `name` (иногда признак разминки). Детальная legacy-библиотека в `index.html` содержит поля вроде категории, оборудования/изображения, мышечных групп, шагов и типичных ошибок, но для этих утверждений в данных не обнаружена ссылка на источник или дата проверки.
- Поэтому заполненное поле не означает проверенное утверждение. Не добавлять целевые мышцы, биомеханику, «безопасность» или медицинские ограничения по догадке.

## Разделение сущностей

**Упражнение** описывает общий каталог. **Предписание программы** описывает конкретную дозировку в рамках дня программы. Не дублировать технику упражнения в каждой программе и не заменять данные истории тренировки изменением каталога.

Для новых/редактируемых записей поддерживать следующий логический набор полей, совместив его с фактической схемой при реализации:

| Поле | Назначение |
|---|---|
| `id` | Стабильный уникальный идентификатор; существующие ID не переиспользовать. |
| `name`, `aliases` | Краткое русское название и проверенные варианты поиска. |
| `movementPattern` | Тип движения, если он явно определён. Не выводить из названия автоматически. |
| `equipment` | Требуемое оборудование; пустое/неизвестное хранить как неизвестное. |
| `primaryMuscles`, `secondaryMuscles` | Основные и вторичные группы отдельно; не приравнивать участие к гарантированному росту. |
| `difficulty` | Уровень только с понятным критерием приложения; не медицинская оценка. |
| `mode` | Повторения, время, дистанция или разминка — согласованная машиночитаемая категория. |
| `technique.steps` | Короткие проверяемые инструкции в порядке выполнения; не переносить из непроверенного источника молча. |
| `technique.cues`, `commonErrors` | Наблюдаемые подсказки и типичные технические ошибки, без обещания профилактики травм. |
| `variants` | Регрессии/прогрессии с пояснением необходимого оборудования и отличий. |
| `limitations` | Ограничения применимости, подтверждённые источником/экспертом; не ставить диагноз и не обещать индивидуальную безопасность. |
| `media` | Автор/источник, лицензия, URL/файл и текст альтернативы для доступности. |
| `sources` | Название, URL/идентификатор, тип источника и дата доступа для каждого значимого утверждения. |
| `verification.status` | `draft`, `source_checked`, `expert_reviewed` или `needs_review`. |
| `verification.checkedAt`, `reviewerRole` | Дата проверки и роль проверившего; не хранить выдуманное имя/квалификацию. |

Пропущенные данные обозначать отсутствием/`null` по принятой схеме, а не вымышленным значением, нулём или общим утверждением. Значения в интерфейсе должны соответствовать уровню проверки.

## Предписание в программе

Сохранять в программе только параметры назначения: ID упражнения, режим, подходы, диапазон повторений/времени, отдых, RIR/запас повторов и контекстную заметку. Проверять, что заметка относится к этому дню/варианту, а не выдаётся за универсальную технику. Разминку и рабочие подходы маркировать отдельно, чтобы они не смешивались при подсчёте объёма.

## Приёмка контента

1. ID устойчив и связан с существующей записью, программа не потеряла предписания.
2. Название и оборудование проверены; дубль/синонимы не создают второе упражнение без причины.
3. Техника не противоречит типу движения и не содержит опасных абсолютных обещаний.
4. Мышечные группы разделены на primary/secondary и подтверждены источником; если доказательств нет — оставить неизвестными.
5. Изображение соответствует варианту и не искажает движение; лицензия/источник известны.
6. Источник, дата и статус проверки заполнены для новых содержательных утверждений.
7. Проверены отображение мобильной карточки и экран упражнения; история подходов пользователя не меняется при редактировании справочника.
