СЛАБОЕ ТЕЛО — приложение для ведения тренировок с аккаунтом и синхронизацией

Локальный запуск
1. Установи Node.js 20 или новее.
2. Открой PowerShell в папке проекта.
3. Запусти: node server.mjs
4. На компьютере открой http://localhost:8766/.
5. По умолчанию сервер доступен только на этом компьютере. Для временного доступа с другого устройства в той же сети останови сервер и запусти его так: в PowerShell выполни `$env:RITM_HOST="0.0.0.0"; node server.mjs`, затем открой на втором устройстве `http://IP-адрес-компьютера:8766/`. Не используй этот режим в публичной сети: HTTP не шифрует пароль.

Создай профиль с логином и паролем от 8 символов. Логин: 3–32 латинских буквы, цифры, точка, дефис или подчёркивание. Пароль хранится в виде хеша scrypt, сессия — в HttpOnly cookie. Для каждого логина создаётся отдельный набор тренировок. Данные хранятся на сервере в data/accounts.json. При первой регистрации сервер попробует перенести существующие записи из localStorage этого браузера; последующие регистрации их не копируют.

Для входа из интернета, вне домашней сети, сервер нужно разместить на доступном хосте за HTTPS reverse proxy и подключить постоянное хранилище папки data. Установи переменную RITM_SECURE_COOKIE=1 для публикации за HTTPS. Не публикуй сервер по обычному HTTP: он не шифрует пароль в пути. Делай резервные копии data/accounts.json и экспорт пользователя в разделе «Профиль». Не загружай эту папку с аккаунтами в публичный репозиторий.

Сторонние библиотеки и регистрация через внешний сервис не нужны. Для поиска продуктов и штрихкодов раздел «Питание» обращается к Open Food Facts через сервер Node.js: текстовый поиск — Search-a-licious, штрихкоды — API v3. Для этой интеграции не нужен ключ; сервер задаёт собственный User-Agent и ограничивает частоту запросов. При недоступности каталога остаются личные продукты и явно помеченные демо-примеры. Найденный товар сохраняется вместе с записью дневника и пищевыми значениями на 100 г, поэтому история остаётся доступной после перезагрузки.

Open Food Facts — база по лицензии ODbL; отдельные сведения о продуктах предоставляются участниками сообщества и могут содержать пропуски. В интерфейсе указаны источник, ссылка на карточку продукта и рекомендация проверить упаковку. Отсутствующие макронутриенты остаются неизвестными и показываются как «—».

В проекте хранится компактный локальный каталог наиболее распространённых продуктов. Повторно запустить безопасное пополнение каталога можно командой `node import-nutrition-catalog.mjs`; импорт добавляет новые штрихкоды и обновляет ранее загруженные записи Open Food Facts, не меняя аккаунты и личные продукты. Поиск сначала обращается к локальному каталогу, затем дополняет выдачу внешним поиском, если совпадений мало. Внешние результаты кэшируются в памяти сервера на короткий срок.

Node-сервер обязателен для входа, синхронизации и поиска продуктов; открытие index.html как статической страницы не включает эти функции.

Админ-панель
Владелец использует свой обычный аккаунт. Серверному процессу передаётся `RITM_ADMIN_LOGIN` — точный логин уже существующего аккаунта. Пароль пользователя остаётся только в штатном входе приложения; отдельный пароль администратора не нужен. PowerShell пример:
`$env:RITM_ADMIN_LOGIN="логин-владельца"; node server.mjs`
На Selectel укажи `RITM_ADMIN_LOGIN` в окружении сервиса и перезапусти его. Админ-пункт появляется в разделе «Ещё» после обычного входа этим аккаунтом. Все административные API дополнительно проверяют роль на сервере. Сводка включает регистрации, активности после включения учёта, тренировки, выбранные программы, упражнения и агрегированные сведения аккаунтов. Пароли и токены не отдаются; обращения к админским данным записываются в журнал `adminAudit` в `data/accounts.json`.

В списке пользователей администратор может назначить или снять роль тренера и открыть краткую статистику аккаунта: число тренировок, последние тренировки, выбранную программу и агрегированные записи питания. Роль тренера назначается только через админ-панель. В тренерском кабинете есть карточки клиентов и вкладки с разрешёнными данными о завершённых тренировках и дневных сводках питания. Тренер может назначить занятие на дату с упражнениями каталога; после принятия оно появляется в личных программах и календаре клиента, затем запускается штатным экраном. После завершения клиент может оставить отзыв о нагрузке и самочувствии, тренер — ответить в карточке назначения; обе стороны получают внутреннее уведомление. Отдельное разрешение управляет предложениями целей КБЖУ; клиент может принять или отклонить их, и только принятие обновляет цели в его дневнике. Тренер также может отправить рекомендацию и предложить готовую программу; фактические записи истории тренировок и еды не редактируются тренером. При снятии роли завершаются активные связи тренера и ожидающие приглашения. Модель аккаунта хранит список ролей для расширения в будущем; роль модератора пока не включена.

Telegram-уведомления от `@SlaboeTeloFitnessBot` реализованы как дополнительный канал уже существующих событий. Токен бота и секрет webhook должны храниться только в защищённом серверном EnvironmentFile; клиентское приложение их не получает. Пользователь привязывает Telegram одноразовой ссылкой и сам включает нужные категории. Порядок настройки после выпуска описан в `deploy/TELEGRAM-SETUP.txt`. До добавления переменных в окружение и регистрации webhook эта возможность остаётся недоступной. Таймер отдыха и напоминания по расписанию пока не отправляются ботом.

Разделы: главная, программа, карточки упражнений, запись подходов и кардио, заметки, восстановление незавершённой тренировки, история, графики активности и рабочих весов, профиль и экспорт данных.

Аватары профиля загружаются в приватную папку `data/avatars`, а в профиле сохраняется случайный ключ файла. Получить или изменить аватар может только владелец авторизованной сессии. При переносе приложения сохраняй `data/avatars` вместе с `data/accounts.json`; папка аватаров исключена из Git.

Безопасность аккаунта
В профиле можно сменить пароль, подтвердив текущий. После этого остальные сессии завершатся. Если пароль забыт, администратор может после проверки владельца выдать одноразовый код восстановления; код действует 30 минут и вводится вместе с логином и новым паролем на экране входа. Сервис не отправляет письма и не проверяет личность автоматически — администратор должен передать код только через подтверждённый канал.

В профиле можно скачать резервную копию, сбросить данные и настройки, выйти или полностью удалить аккаунт. Сброс сохраняет сам аккаунт; удаление требует текущий пароль и точный логин, необратимо удаляет данные и тренерские связи. Перед удалением сначала экспортируй резервную копию. Аккаунт, указанный в `RITM_ADMIN_LOGIN`, удалить нельзя: сначала назначь администратором другой действующий аккаунт.

Обновление установленной версии
Код приложения можно обновлять отдельно от аккаунтов. На сервере храни `RITM_DATA_DIR` в постоянной папке вне каталогов релизов (для текущей установки используется `/var/lib/slaboetelo`) и никогда не заменяй её файлами локальной копии. Перед выпуском сравни локальный проект с текущим серверным релизом и перенеси только изменённые исходники и новые/обновлённые файлы из `assets`; состав пакета зависит от конкретного изменения. Если изменён `server.mjs` или серверный модуль, после копирования перезапусти `slaboetelo`; изменения только в `index.html` и клиентских скриптах обычно подхватываются без перезапуска Node. Статические файлы приложения отдаются с `Cache-Control: no-cache`, чтобы при следующем открытии браузер запрашивал актуальную версию.

Для безопасного отката используй каталоги релизов: подготовь новый каталог на основе текущего серверного релиза, наложи в него только проверенные изменения, затем переключи systemd на новый каталог и перезапусти сервис. Старый каталог оставь доступным до проверки входа, главной страницы и сохранения данных; при проблеме верни systemd на предыдущий каталог. Папки `data/accounts.json` и `data/avatars` должны оставаться общими и постоянными между релизами. Перед первым переходом на каталоги релизов проверь действующий `WorkingDirectory`, `ExecStart` и `RITM_DATA_DIR` в unit-файле: локальная проверка не подтверждает настройки работающего сервера.
